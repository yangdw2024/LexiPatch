# 译核 TransCore — 软件汉化包生成平台

## 一、软件简介

**译核 TransCore** 是一款专业的桌面端软件汉化工具，帮助开发者和汉化爱好者将任意软件的界面文字资源文件（如 JSON、properties、XML 等）进行解析、翻译、审校，并最终打包为可部署的汉化包。

核心优势：
- 支持 **7 种主流资源文件格式** 的自动识别与解析
- 内置 **智能机翻引擎**（术语库匹配 + 翻译记忆）
- 完整的 **汉化工作流**：项目管理 → 翻译 → 审校 → 打包
- 一键生成包含 `localized/` 目录、`README.txt` 和 `manifest.json` 的标准汉化包

---

## 二、支持的文件格式

| 格式 | 扩展名 | 典型用途 |
|------|--------|----------|
| **JSON** | `.json` | Web 应用、Node.js、Electron 等 |
| **properties** | `.properties` | Java 应用、Android 资源 |
| **INI** | `.ini` / `.cfg` / `.conf` | Windows 配置文件 |
| **PO** | `.po` / `.pot` | GNU gettext 国际化标准 |
| **YAML** | `.yaml` / `.yml` | 配置文件、数据序列化 |
| **XML** | `.xml` | 通用标记语言、Android strings.xml |
| **RESX** | `.resx` | .NET / C# 资源文件 |

软件会自动检测文件格式，无需手动指定。

## 三、核心功能详解

### 3.1 新建汉化项目

点击「新建汉化项目」，填写基本信息：
- **项目名称**：用于识别和管理
- **目标软件**：要汉化的软件名称
- **资源格式**：选择主要格式（也可自动检测）
- **版本号**：目标软件的版本

上传资源文件后，软件会自动解析文件中的所有字符串条目，提取需要翻译的内容。

### 3.2 翻译工作台

翻译工作台采用三栏布局：

```
┌─────────────────────────────────────────────────────────────────┐
│  文件树（左侧）         │  字符串列表（中间）         │  编辑器（右侧）        │
│  ├─ app.json           │  ├─ menu.file       [英]   │  ┌──────────┐ ┌──────────┐│
│  │  ├─ menu.file       │  ├─ menu.edit       [中]   │  │ File     │ │ 文件     ││
│  │  ├─ menu.edit       │  ├─ btn.save        [机]   │  │          │ │          ││
│  │  └─ btn.save        │  ├─ dialog.warn     [审]   │  │ Edit     │ │ 编辑     ││
│  └─ messages.properties│  └─ ...             [未]   │  │          │ │          ││
│                        │                      │      │  └──────────┘ └──────────┘│
│                        │ 状态颜色:            │      │  原文（上）    译文（下）    │
│                        │ 蓝=已翻译 绿=已审校   │      │                │          │
│                        │ 紫=机翻 灰=未翻译      │      │  术语建议（下方）        │
└─────────────────────────────────────────────────────────────────┘
```

**翻译状态说明**：
- 🟦 **未翻译**：原文未处理
- 🟪 **机翻**：自动翻译生成的初稿
- 🟦 **已翻译**：人工修改后的译文
- 🟩 **已审校**：经过审校确认的译文
- 🟥 **存疑**：标记为需要复核的条目

### 3.3 智能机翻引擎

点击「运行机翻」按钮，系统会自动处理所有未翻译的字符串：

**翻译优先级**：
1. **术语库精确匹配** → 完全一致的术语优先使用预设译文
2. **翻译记忆模糊匹配** → 相似句子按相似度（Levenshtein 算法）匹配
3. **内置 UI 词典** → 约 200 条高频界面词汇（如 "File", "Save", "OK" 等）
4. **规则替换** → 常见缩写和格式转换

### 3.4 术语库管理

术语库用于确保同一术语在整个项目中翻译一致：

- **全局术语**：适用于所有项目（如 "OK" → "确定"）
- **项目术语**：仅适用于当前项目（如 "API" → "应用程序接口" 或保留 "API"）
- **不翻译**标记：专有名词、品牌名等无需翻译的词汇

### 3.5 打包发布

翻译完成后，进入「打包发布」页面：

**三种导出策略**：

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **原格式回写** | 按资源文件原始格式生成译文 | 直接覆盖部署到软件目录 |
| **统一 JSON** | 所有文件统一输出为 JSON 格式 | 需要二次处理或自定义加载 |
| **多格式并存** | 同时输出原格式与 JSON 两套 | 兼容多种加载方式 |

**生成的汉化包结构**：

```
汉化包.zip/
├── localized/           # 译文文件目录（按原结构）
│   ├── app.json
│   ├── messages.properties
│   └── strings.xml
├── README.txt           # 使用说明（含版本、统计、部署指南）
└── manifest.json        # 元数据（版本、统计、文件清单）
```

## 四、使用流程

```
① 创建项目
    ↓
② 上传资源文件（自动解析）
    ↓
③ 运行机翻（或手动翻译）
    ↓
④ 人工审校修改
    ↓
⑤ 添加/管理术语（可选）
    ↓
⑥ 选择导出策略
    ↓
⑦ 打包并下载汉化包 ZIP
    ↓
⑧ 将 localized/ 目录覆盖到软件安装目录
```

## 六、常见问题

### Q1：上传文件后看不到字符串？

A：请检查文件格式是否正确。目前支持 JSON、properties、INI、PO、YAML、XML、RESX 七种格式。如果是自定义格式，可尝试转为 JSON 格式导入。

### Q2：机翻效果不好怎么办？

A：
1. 在「术语库」中添加项目专用术语
2. 在翻译工作台中手动修改不满意的译文
3. 使用「翻译记忆」功能积累常用句子

### Q3：汉化包如何部署？

A：解压 ZIP 后，将 `localized/` 目录中的文件覆盖到目标软件的对应资源目录即可。具体路径需根据软件实际结构确定。

### Q4：数据保存在哪里？

A：项目数据保存在本地浏览器的 localStorage 中（Electron 内部浏览器），不会上传到服务器。
